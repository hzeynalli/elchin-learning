# Design language — "Overworld" (Minecraft-inspired, decided 9 Sep 2026)

The app is for a 10-year-old who plays Minecraft. The skin borrows Minecraft's *visual grammar* — blocky, bevelled,
pixel-font headings, inventory-style panels, an XP bar, hearts, "Achievement get!" toasts — without copying any Mojang
asset. Every texture is a 16×16 PNG generated by us (`styles.css` `--tex-*`), scaled with `image-rendering: pixelated`.

## Palette
- Sky `#78A7FF → #C9E4FF` (page). Ground strip fixed at the bottom: grass over dirt (student), cobble over stone (parent).
- GUI grey `#C6C6C6` panels with 3 px bevel (white top/left, `#555` bottom/right) and a 2 px black outline — the inventory look.
- Buttons: stone grey `#6E6E6E` with bevel; **primary action = green `#3C8527`** ("Enter world", "Start", "Save");
  gold `#C99A1E` for rewards. Hover = blue-grey `#7E8CC5`; pressed = 2 px translate; focus = 3 px white ring.
- Inputs are black with a light bevel (Minecraft text fields), white bold text.
- Status = block textures, never bare colour: **Not yet = stone · Getting there = copper · Secure = grass · Mastered =
  diamond · Locked = bedrock + 🔒**. Subjects: Maths = diamond, Reading = planks, Language = gold, Science = emerald.
- Red is used only for the streak hearts. No red/green for right/wrong: correct = green panel, "Not this time" = copper panel.

## Type
- `Press Start 2P` (Google Fonts) for headings, buttons, labels and the HUD — always ≥ 0.5 rem, short strings, uppercase
  where it reads as a label. It has no arrow/em-dash glyphs: write "to", "per", "-" instead of → and —.
- `Nunito` 500/700/800 for everything a child reads: 18 px base for the student, 15 px for the parent.

## Screens
- **Header/HUD**: title, level + XP bar (100 points = 1 level, cosmetic), 10 hearts = day streak, sign out.
- **Hotbar** navigation: Home · Quests · Map (· Coach when `FEATURES.coach`) · Parent. Active slot = white outline.
- **Home**: three numbered quests in fixed order (Daily review → Topic quest → Story quest), week stats, Treasure chest.
- **Quests**: one card per subject (Big quest = adaptive check over open topics, Practice quest = weak spots, Story quest),
  games (Memory game, Boss quest), the topic list by term with locked rows, recent quests table.
- **Map**: every topic is a block tile grouped subject → term (Last year / Semester 1 / Semester 2); GO on open tiles.
- **Question screen**: one question, huge stem, big option buttons with A/B/C/D keys, "Check", feedback panel, "Next".
  Timer top-right in a small dark chip, never alarming. Results = score block on grass + per-topic bars.
- **Parent**: same skin, denser; Overview (subject table, KPIs, tutor list), **Unlock topics** (checkbox table by term
  with Open/Lock all, gating switch, explicit Save), paper diagnostic, marking queue, rewards, MAP, settings, exports.

## Words in the student UI
Quest, Big quest, Practice quest, Story quest, Daily review, Memory game, Boss quest, Check, Try again, Next,
Done for today, Getting there, Locked — ask Dad. Never "test", "exam", "fail".

## Accessibility & states
Semantic buttons, visible focus rings, `aria-pressed` on option cards, `role=progressbar` on the XP bar, skip link,
`prefers-reduced-motion` (no animation), `prefers-contrast: more` (stronger outlines), print styles. Every button has
default / hover / pressed / focus / disabled; option cards have a selected state; results and lists have empty states.

## Preview
`index.html?preview=1` (add `&role=parent`, `&tab=map`, `&start=diagnostic`) renders the whole app with fictional data
and writes nothing — use it to review the design without logging in.
