## 0. How to resume at the office (10 minutes)

1. `git clone https://github.com/hzeynalli/elchin-learning ~/Projects/elchin-learning` (or open the OneDrive copy).
2. Copy `.env` from the OneDrive folder into the repo root (it holds the two logins and the public keys).
3. `cd worker && npm install && npm test` → all tests should pass (see counts below).
4. **Get the two secrets the laptop could not obtain** (see §2) and put them in `worker/.dev.vars` (copy `.dev.vars.example`).
5. `cd worker && npx wrangler login` (one browser click), then `npx wrangler secret put ANTHROPIC_API_KEY`,
   `… SUPABASE_URL`, `… SUPABASE_SERVICE_KEY`, `… SUPABASE_ANON_KEY`, then `npx wrangler deploy`.
6. Put the deployed Worker URL into `config.js` → `WORKER_URL`, commit, push. Add the Pages/Worker origin to
   `ALLOWED_ORIGINS` in `worker/wrangler.toml` if it differs.
7. Serve the front-end: either enable GitHub Pages (needs the repo public, or GitHub Pro) **or** simply open the Worker
   URL — `wrangler.toml [assets]` serves `index.html` from the repo root, so the Worker *is* the site (same origin,
   no CORS). This is the recommended path while the repo stays private.
8. Log in as parent, enter the paper Diagnostic 1 scorecard (Parent → Paper diagnostic), then log in as Elchin.
9. Continue with the next phase in "Status by phase". Tell Claude Code: *"Read HANDOFF.md and continue from the next
   unchecked item."*

## 2. What the office must do first (things this laptop could not do)

   generation and marking in **MOCK mode** (deterministic canned replies; `llm_mode: "mock"` in `/dashboard`).
   Create one at platform.claude.com → set as Worker secret `ANTHROPIC_API_KEY`.

   user's own JWT) but **every write returns 503** with a clear message. Set as Worker secret `SUPABASE_SERVICE_KEY`.

## 3. Decisions and interpretations to confirm (I chose; you can veto)

- **Canonical maths skills = `skills_math_ccss.json` (38)**; the QSI file's ids (`G4.4`, `E02.5`…) are aliases stored in
  `skills.aliases` and mapped in `data/qsi_crosswalk.json`. The paper diagnostic's 29 questions map onto 18 canonical
  skills; both `E01.1` and `E01.2` map to `5.MP.1`; `G4.7` splits into `G4.NF.1` (Q9) and `G4.NF.2` (Q10).
- **Mastery rule reading** (`worker/src/mastery.js` header): a Secure/Mastered skill scoring 0.7–0.89 on an ordinary
  test keeps its status but loses its clean streak; only < 0.7 (regression) or a failed review demotes. "Two
  consecutive ≥ 0.9 with at least one tier-3 correct" = across those two tests together. Fluency skills need
  `mean_time_s ≤ 3` to pass. Practice retry-correct = 0.5; confirm retry = 0.
- **FSRS-lite constants**: docs/06 prints `e^0.6 · (11−D) · S^−0.2 · (e^{0.1(1−R)} − 1)`, which gives ~10 % growth per
  review and cannot produce the "≈ 2, 6, 15, 35, 80, 180 days" schedule the same section promises. Implemented with
  FSRS's published defaults (w8 = 1.49, w9 = 0.14, w10 = 0.94) as parameters → 2, 6, 18, 50, 125, 290 days, capped at
  3×S per step. Change `FSRS` in `scheduler.js` if you prefer other values.
- **Paper Q4 (six times-table facts)** is stored as six items so the fluency skill `G4.OA.F` gets qualifying
  evidence; per-fact time = seconds entered ÷ 6; `fast` if ≤ 3 s (the key's "under 20 s" ≈ 3.3 s, so 18 s is the
  practical cut-off).
- **Schema additions** (additive only): `skills.aliases/planned_month/fluency/map_area`, `skill_state.reviews_passed`,
  `tests.loop_id`, `coach_sessions.off_topic_hits/active_s`, `passages.questions`, tables `explanations`, `llm_usage`;
  `test_kind_t` gained `knowledge_check`, `map_mock`. RLS enabled on every table (the package left six without).
- **Profiles policy** rewritten with a `security definer` function — the package's self-referencing policy would have
  recursed infinitely in Postgres.
- **Student tab is labelled "Checks"**, not "Tests" (design-language.md bans "test" in the student UI; BRIEF §7 names
  the tab "Tests" — the more specific rule won). Parent view keeps the word.
- **Temperature 0** (prompts/mark_prompt.md, verification) is not available on Sonnet 5 / Fable 5.1 (no sampling
  params); approximated with `output_config.effort: "low"` and JSON-only instructions plus a repair retry.
- **Worker uses two Supabase clients**: user JWT (RLS-scoped) for reads, service key for writes — least privilege and
  it made the read paths testable before the service key existed.
- **Repo is private**; GitHub Pages on a private repo needs Pro, so `wrangler.toml [assets]` serves the site from the
  Worker (`.assetsignore` hides docs/data/worker). Both hosting options stay open.

## 5. FIRST_PROMPT.md answers (for the owner to check)

1. **Goal / 1 Oct scope.** A private one-page web app where Elchin (10, QSI Baku, US Grade 5) is diagnosed, coached and
   re-tested until each tracked skill is Secure — first the 35 priority-1 skills tied to QSI Math E01–E02, Reading
   E01–E02, Writing E01–E02 by **1 October 2026**, then every MAP strand as a rolling target through the year with a
   retention engine so September skills are still held in March. Huseyn sees everything; Phase 0 (paper diagnostic +
   chat coaching) runs in parallel and its results are entered by hand so the app never starts empty.
2. **Mastery rules (docs/02 §3).** Qualifying test = ≥ 3 items on the skill. Not yet: no data or last rate < 0.5.
   Emerging: 0.5–0.89, or a 4/4 diagnostic with no confirmation, or practice passed but confirm not yet. Secure:
   practice ≥ 0.9 **and** confirm ≥ 0.9 in the same loop, or two consecutive qualifying tests ≥ 0.9 with a tier-3
   item correct. Mastered: Secure then two passed scheduled reviews. Regression: any qualifying test < 0.7 → Emerging
   and the review chain is cleared. Fluency skills also need ≥ 90 % at ≤ 3 s per item.
   **Coach state machine (docs/02 §2).** EXPLAIN_n (activate prior knowledge → small steps → worked example → faded
   example → explain it back; representation rotates every cycle) → PRACTICE_10 (7×t2 + 3×t1, hint + one retry at 0.5)
   → pass ≥ 0.9 → CONFIRM_5 (≥ 3×t3, no retry credit; single tier-3 slip with correct method → one replacement item)
   → pass → SECURE → spaced reviews; any fail → next EXPLAIN with a new representation; after 3 cycles suggest a
   break and flag the parent; never repeat an item.
3. **Maths verification rule (docs/03 §3).** Every numeric answer is computed in code by a seeded template generator
   and covered by ≥ 20 unit tests with an independent computation; LLM-worded word problems ship only if a second
   cold-solve call equals the coded answer.
4. **Accounts/keys.** Supabase (done), Cloudflare (`npx wrangler login`, then `wrangler secret put` ×4, `wrangler
   deploy`), Anthropic API key, GitHub repo (done), ElevenLabs later. Exact commands in §0.
5. **Phase 1 checklist + acceptance** — §4 above, all items verified except deploy and live writes.
